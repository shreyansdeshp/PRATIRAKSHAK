# Snapshot contract (`frontend/public/data/`)

The front-end runs entirely from these files. They are generated by `python -m pratirakshak.export` (`./tasks.ps1 export`) and validated against the schemas in `backend/pratirakshak/export/schema.py`.

- **Bytes:** deterministic (no wall-clock timestamps); total ≈ 4 MB, limit 25 MB.
- **No future truth:** engine life lengths and latent damage never appear in these files.
- **Roles:** listed in `meta.json → roles`. The vendor shell loads only `vendor.json`.

| File | Contents | Provenance |
|---|---|---|
| `meta.json` | project, seed 26249, demo seed, snapshot clock "D+0 06:00Z", provenance legend, roles → files | — |
| `manifest.json` | every file with bytes and a sha256 prefix (used by the service worker) | — |
| `world.json` | bases (+ D+0 environment), nodes, aircraft types, systems, 72 aircraft (no engine life truth), parts, stock, routes (geometry files under `routes/`) | ILLUSTRATIVE names · REAL-ANCHORED climate, roads |
| `state.json` | per tail: status, limiting system, risk in window, weighted & body health, recommended action, and 8 systems × {health, P(fail in 14 d), RUL p10/p50/p90 days, provenance, confidence, drivers}; fleet / base / type roll-ups | engines REAL, others SIMULATED |
| `history.json` | 61-day system-sensor series per tail (faults included), trust per sensor with reasons, engine headline sensors as deviation from healthy baseline (last ≤ 60 cycles, sensor units) | REAL (engines) · SIMULATED |
| `decisions.json` | D+0 decision per tail with reason cards (what / why / how sure / key sensors / alternatives / spares) | SIMULATED |
| `plan.json` | CP-SAT hangar plan (visits, bays, capacities, solver stats) + mission-fit shortlists | SIMULATED |
| `intelligence.json` | sensor → part → LRU → action graph with importance, trust-harness results, engine importance per subset, flagged sensors | REAL · SIMULATED |
| `models.json` | engine model metrics (accuracy, calibration, alarms), system models vs synthetic truth, hydraulics anchor, data verification | REAL · REAL-ANCHORED · SIMULATED |
| `results.json` | policy × scenario metrics with 95 % CIs, paired differences, daily ready curves, ablations, sensitivity, counterfactuals | SIMULATED |
| `demo.json` | demo-seed event logs (failures, pulls, hangar visits) for P0–P3 and P3 with late detection | SIMULATED |
| `twin.json` | default 60-day condition fans (p10/p50/p90) and risk-of-any-failure curve per tail | SIMULATED |
| `vendor.json` | **vendor role only:** demands (id, part, qty, priority, destination, deliver-by, source, mode, ETA, route), hub stock, node locations. No tail ids, health or readiness (tested) | ILLUSTRATIVE |

**Live API (optional):** `python -m uvicorn pratirakshak.api.app:app --port 8000`

| Endpoint | Purpose |
|---|---|
| `GET /api/health` | liveness check |
| `POST /api/twin` | what-if: usage multiplier, deferral, service, environment |
| `POST /api/resimulate` | one seed of a scenario × policy |
| `POST /api/decision` | re-run the rule at another θ or criticality |
| `GET /api/vendor/demands` | vendor subset only |

The front-end probes `/api/health` once (1.2 s timeout) and falls back to the static files silently.
